# VSIX Downloader

Интерактивная утилита для скачивания конкретной версии расширения VS Code с официального Visual Studio Marketplace. Работает на Windows и Linux. Загрузка не требует запущенного VS Code и не устанавливает расширения.

## Запуск

На **Windows x64** запустите `vsix-downloader.exe` из Проводника или терминала. Можно перенести только этот файл в любую папку. Отдельные DLL и установленный .NET не нужны.

Для запуска из исходников на Windows или Linux нужен [.NET 11 SDK](https://dotnet.microsoft.com/download/dotnet/11.0) и интерактивный терминал.

```sh
dotnet run --project src/VsixDownloader
```

1. Если нужен прокси, откройте **Настройки → Прокси** и введите, например, `http://proxy.example:8080`. Пустое значение означает прямое соединение. Утилита не читает системный прокси и переменные `*_PROXY`, логин и пароль не поддерживаются. Один URL применяется к Marketplace и к загрузке с CDN.
2. Введите `publisher.extension`, например `ms-vscode.cpptools`. Выберите точную версию, затем одну, несколько или все доступные сборки. Версии pre-release отмечены отдельно. `universal` означает один пакет без платформенной привязки, а не отдельный файл для каждой ОС.
3. Выберите папку. По умолчанию это `downloads` в текущем каталоге. Файл именуется `<publisher.extension>-<version>-<platform>.vsix`. Подходящий файл, который уже есть в папке, повторно не скачивается. Утилита не перезаписывает существующий VSIX, если его манифест не совпадает с выбранной сборкой.

Настройки сохраняются в профиле пользователя. Точный путь к файлу настроек отображается после сохранения. В меню **Таймауты и попытки** можно изменить значения по умолчанию.

| Настройка | По умолчанию |
|---|---:|
| Установка соединения | 30 с |
| Ожидание заголовков при скачивании, включая перенаправления | 120 с |
| Допустимая пауза между порциями данных | 180 с |
| Попытки скачать один файл, включая первую | 5 |

Для запроса каталога таймаут ожидания ответа распространяется и на чтение JSON. У загрузки VSIX нет общего лимита длительности. Пока поступают данные, низкая скорость сама по себе не прерывает загрузку.

## Как работает докачка

Байты пишутся в `.part`, служебные файлы лежат в подкаталоге `.vsix-downloader`. При обрыве утилита повторяет запрос с `Range` и `If-Range`, если у неё есть надёжный идентификатор того же HTTP-представления. Если попытки исчерпаны или нажали Ctrl+C, выберите тот же пакет и ту же папку при следующем запуске. Если CDN или прокси не поддерживает диапазоны, либо ответ не совпадает с записанной частью, загрузка начнётся сначала. После успешной загрузки утилита проверяет VSIX и перемещает его в конечное имя.

Установка скачанного пакета при необходимости выполняется отдельно в VS Code командой **Extensions: Install from VSIX**.

## Разработка

Сборка автономного EXE для Windows x64 из корня проекта:

```sh
dotnet publish src/VsixDownloader -c Release -p:PublishProfile=win-x64
```

Готовый файл находится в `src/VsixDownloader/bin/Release/net11.0/win-x64/publish/vsix-downloader.exe`.

Среда .NET и библиотеки приложения упакованы в EXE. Если при запуске библиотекам нужна распаковка, .NET делает это автоматически во временном каталоге. Настройки и скачанные VSIX по-прежнему хранятся отдельно от программы.

```sh
dotnet test VsixDownloader.slnx
```

Тесты работают без внешней сети. Для проверки с реальным Marketplace попробуйте расширение с несколькими платформами, например `ms-vscode.cpptools`, одну из его версий и два целевых пакета. Затем прервите одну загрузку и повторите те же параметры, чтобы проверить докачку через свой прокси.
